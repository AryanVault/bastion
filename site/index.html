Why Bastion

There are a hundred AI assistants. Most of them trust the AI.

An assistant that reads your email can be talked into things by the email itself. That’s prompt injection, and no model is immune to it. Most assistants ask the model to be careful. Bastion assumes the model will be fooled, and puts the rules in code that words can’t reach.

Bastion is for you if

  • you want an assistant with real access to your email and calendar, without handing a chatbot the keys;
  • you’d rather it ran on hardware you control, with a model you pick;
  • you want to read the code and the threat model before you trust it.

It’s not for you if

  • you want zero setup: a hosted assistant is easier, and that’s a fair trade;
  • you need it to browse websites for you or run code: it deliberately can’t, yet;
  • you need a shared assistant for a team: it’s paired to one person.

Some attacks are invisible

This message carries a second sentence written in Unicode “tag” characters. You can’t see it. Many AI models can read it. Bastion strips these characters before untrusted text reaches a model, and shows them in every approval.

How it works

The AI proposes. Code decides.

Every action the model asks for passes the same checks, written in plain, tested code. None of them can be talked out of their job.

  1. ProposalThe model asks to use a tool.
  2. Allow-listUnknown tools are refused.
  3. SchemaArguments must match exactly.
  4. PolicyRisk tier plus taint: allow, ask or deny.
  5. YouApprove the exact arguments, with your code.
  6. ToolRuns with a timeout. Untrusted output is fenced.
  7. AuditEvery step goes in a tamper-evident log.

Taint tracking

Once an email, page or invite is in the conversation, anything outward-facing needs your approval and anything destructive is refused.

A quarantined reader

Email is summarised by a separate model call that has no tools, so attacker text never steers the planner directly.

Links it can’t be tricked into

It only opens links you sent or a search returned, and checks every connection against your home network and cloud metadata addresses.

Sealed at rest

Keys live in your OS keychain. Memory and tasks are AES-GCM encrypted, and the audit log is HMAC-chained, with checkpoints sent to your phone.

Scheduled tasks on a leash

Each task gets a fixed set of tools and a budget when you approve it, and its definition is sealed so nothing can widen it later.

Releases you can verify

Signed build provenance, an SBOM, and a hardened container that runs as a non-root user with a read-only filesystem.

Get started

Running on your computer in about ten minutes.

You need Windows, macOS or Linux, and an API key from an AI provider (or Ollama, for a model that runs on your machine). The installer fetches the right Python for you.

Terminal
  1. # 1. Install uv (macOS, Linux; Windows steps are in the guide)
  2. curl -LsSf https://astral.sh/uv/install.sh | sh
  3. # 2. Install Bastion
  4. uv tool install git+https://github.com/AryanVault/bastion
  5. # 3. Pick your AI model and add its key (kept in your keychain)
  6. bastion init
  7. # 4. Say hello
  8. bastion chat

Then put it on your phone with bastion telegram setup, connect Gmail and Calendar, and schedule tasks. The guide walks through each step.
